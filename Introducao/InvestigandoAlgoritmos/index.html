Item 01Machine Learning no Cotidiano
Tecnologias que já fazem parte da nossa rotina

Nas grandes cidades, é comum recorrermos a aplicativos de navegação para encontrar a melhor rota em tempo real, evitando trânsito e economizando tempo. Em viagens ao exterior, aplicativos de tradução instantânea convertem frases em tempo real, com vozes que capturam até as emoções do texto — longe de soar robótico ou artificial.

O que está por trás dessas tecnologias, que carregamos no bolso em nossos smartphones, é o Machine Learning — aprendizado de máquina —, uma abordagem da Inteligência Artificial que tem ganhado protagonismo crescente no nosso cotidiano.

Compreendendo o papel do Machine Learning

Machine Learning é a abordagem por trás dos LLMs (Large Language Models) — os grandes modelos de linguagem que sustentam ferramentas como ChatGPT, Google Gemini e DeepSeek. À primeira vista pode parecer território exclusivo de especialistas em estatística ou ciência de dados, mas não é: qualquer pessoa pode explorar modelos de ML e aplicá-los em problemas reais.

Aprendizado Supervisionado

O modelo aprende a partir de dados com rótulos conhecidos — como imagens de flores identificadas por espécie.

Aprendizado Não Supervisionado

Sem rótulos: o algoritmo descobre padrões por conta própria — agrupando dados semelhantes (clusterização).

Aprendizado por Reforço

O agente aprende interagindo com o ambiente, recebendo recompensas por boas decisões — base de jogos de IA.

Visão Computacional e PLN

Subáreas que tratam de imagens e linguagem natural — os pilares do ChatGPT, Gemini e sistemas de reconhecimento facial.

Google Colaboratory — nosso ambiente de trabalho

Para explorar o Machine Learning de forma prática, utilizaremos o Google Colaboratory (Google Colab), uma ferramenta gratuita disponível na web. Basta acessar sua conta Google, abrir um notebook e executar código Python diretamente no navegador.

Vantagem principal: não é necessário configurar nenhum ambiente local, instalar bibliotecas ou resolver dependências. Você vai direto ao código de forma simples e rápida — ideal para aprender e experimentar.
Item 02Classificando Flores com Python
Utilizando dados para treinar a máquina

Para o aprendizado de máquina, utilizamos muitos dados. Em ML, ensinar a máquina a "pensar" significa expô-la a exemplos suficientes para que ela extraia padrões por conta própria. Quanto mais representativos e bem estruturados os dados, melhor o modelo resultante.

Conhecendo o Dataset Iris

O Dataset Iris é um dos conjuntos de dados mais antigos e conhecidos no mundo da IA — amplamente usado em testes de Machine Learning. Ele contém informações sobre três espécies de flores do tipo íris:

  • Iris setosa — pétalas menores e mais arredondadas
  • Iris versicolor — tamanho e forma intermediários
  • Iris virginica — pétalas maiores e mais alongadas

Cada amostra possui quatro atributos medidos: comprimento e largura da pétala, comprimento e largura da sépala. O objetivo é treinar um algoritmo capaz de classificar corretamente cada flor com base nessas medidas — um caso clássico de aprendizado supervisionado.

O que este código faz: O foco deste código é treinar um classificador de Árvore de Decisão para identificar espécies de flores do tipo íris. Importamos o Scikit-Learn com as ferramentas de dataset, divisão de dados, modelo e métricas. Carregamos o dataset Iris (150 amostras com 4 atributos cada), dividimos os dados em 70% para treino e 30% para teste, treinamos a Árvore de Decisão e avaliamos seu desempenho. Ao final, o código exibe a acurácia do modelo — a proporção de flores classificadas corretamente nos dados de teste.
Python 🐍 — classificador_iris.py 
# ── Bloco 1: Importações ────────────────────────────────────────────
from sklearn.datasets import load_iris
# → load_iris() é para carregar o dataset Iris já embutido no scikit-learn
#   — 150 amostras de flores com 4 atributos e 3 classes (espécies) já rotuladas

from sklearn.model_selection import train_test_split
# → train_test_split() é para dividir os dados em dois grupos:
#   treino (para o modelo aprender) e teste (para avaliar o resultado)

from sklearn.tree import DecisionTreeClassifier
# → DecisionTreeClassifier é para criar a Árvore de Decisão — algoritmo que
#   aprende regras do tipo "se largura da pétala > X → espécie Y"

from sklearn.metrics import accuracy_score
# → accuracy_score() é para calcular a porcentagem de classificações corretas

# ── Bloco 2: Carregar os dados ──────────────────────────────────────
iris = load_iris()
X = iris.data    # características: comprimento/largura de pétalas e sépalas (150 × 4)
y = iris.target  # rótulos: 0 = setosa · 1 = versicolor · 2 = virginica

# ── Bloco 3: Dividir em treino e teste ──────────────────────────────
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)
# → 70% dos dados vão para treino (X_train, y_train)
# → 30% ficam reservados para teste  (X_test,  y_test)
# → random_state=42 garante que a divisão seja idêntica toda vez que o código rodar

# ── Bloco 4: Criar e treinar o modelo ───────────────────────────────
model = DecisionTreeClassifier()
# → cria a Árvore de Decisão com configurações padrão
model.fit(X_train, y_train)
# → fit() é o passo do treinamento: o modelo analisa os dados e aprende
#   a separar as três espécies com base nos atributos das flores

# ── Bloco 5: Fazer previsões e avaliar ──────────────────────────────
y_pred = model.predict(X_test)
# → predict() aplica o modelo treinado nos dados de teste (que ele nunca viu antes)
accuracy = accuracy_score(y_test, y_pred)
# → compara os rótulos previstos (y_pred) com os rótulos reais (y_test)
print(f"Acurácia do modelo: {accuracy * 100:.2f}%")
# → exibe o resultado: a proporção de flores classificadas corretamente
Resultado: Acurácia do modelo: 100.00%
Análise dos resultados

O modelo atingiu 100% de acurácia — o que faz sentido dado que o dataset Iris é bem estruturado, com fronteiras bem definidas entre as três espécies. Esse alto desempenho não é comum em problemas reais; na prática, a precisão depende diretamente da qualidade e diversidade dos dados.

O mesmo princípio pode ser aplicado a outros problemas: com um dataset de animais de estimação, poderíamos treinar um modelo para classificar cães, gatos e outros animais — embora a acurácia provavelmente seria menor, refletindo a complexidade maior das imagens.

Machine Learning, em essência, é ensinar máquinas a realizar tarefas específicas com base em exemplos. Quanto mais bem estruturado o conjunto de dados de treinamento, mais preciso e confiável será o modelo resultante.

Item 03Para Saber Mais: Modelos e Aprendizado Supervisionado
O que é um modelo em Machine Learning?

No exemplo anterior, exploramos um caso clássico de Aprendizado Supervisionado. Nessa abordagem, um modelo é treinado com dados que já possuem respostas “corretas”, conhecidas como rótulos. No caso do Dataset Iris, os rótulos são as espécies das flores (Setosa, Versicolour e Virginica).

Mas o que é um modelo no contexto de Machine Learning? Um modelo é como uma “fórmula matemática” que aprende a identificar padrões nos dados. Ele é criado durante o treinamento, quando o algoritmo analisa as características dos dados (como o comprimento e a largura das pétalas e sépalas) e descobre como elas se relacionam com os rótulos.

Utilizamos um modelo de Árvore de Decisão, que funciona como um fluxograma: ele faz perguntas sobre as características das flores (por exemplo, “O comprimento da pétala é maior que 2 cm?”) e, com base nas respostas, decide a qual espécie a flor pertence.

O papel do modelo é generalizar o conhecimento obtido durante o treinamento — sendo capaz de fazer previsões precisas mesmo para dados que nunca viu antes. Por isso, dividimos os dados em dois conjuntos: um para treinar o modelo e outro para testá-lo.
Item 04Analisando o desempenho de modelos

No aprendizado de máquina supervisionado, não basta apenas escolher o modelo, treiná-lo e testá-lo observando a acurácia para garantir um desempenho significativo. É essencial entender como esse modelo se comporta sob diferentes perspectivas. Isso permite verificar se ele possui uma boa capacidade de previsão e se evita a identificação de padrões inexistentes — como classificar incorretamente o subtipo de uma flor do tipo íris ou o tipo de um animal em uma imagem. Esse mesmo princípio se aplica a problemas mais complexos, como a detecção de fraudes.

Garantindo previsões confiáveis

Se quisermos, por exemplo, detectar um e-mail como spam, é fundamental que o modelo faça essa classificação corretamente. Um erro nesse processo pode permitir que um e-mail indesejado chegue à caixa de entrada e potencialmente cause prejuízos. Portanto, garantir o bom desempenho dos modelos com os quais trabalhamos é essencial para obter previsões confiáveis e seguras.

Criando um conjunto de dados para análise

Para aprofundar essa análise, utilizaremos um novo conjunto de dados. Desta vez, desenvolveremos um algoritmo para prever o preço de um imóvel. Em vez de um dataset existente, geraremos nosso próprio conjunto de dados. Para isso, continuaremos no Colab, no mesmo arquivo em que estamos trabalhando, e colaremos um novo código.

No passo seguinte, faremos a divisão em Features e Labels. As Features são as características dos dados — neste caso, o tamanho do imóvel. As Labels são os rótulos ou classificações — neste caso, o preço do imóvel, ou seja, a saída desejada do modelo. Utilizaremos o modelo de Regressão Linear, que consiste em uma função polinomial de primeiro grau: y = ax + b.

O que este código faz: O foco deste código é construir um modelo de Regressão Linear para prever o preço de imóveis com base no tamanho em m². Importamos as bibliotecas necessárias (NumPy, Matplotlib e Scikit-Learn), geramos um dataset de 100 imóveis, definimos as Features (tamanho do imóvel) e as Labels (preço), e dividimos os dados em 80% para treino e 20% para teste. Treinamos o modelo com LinearRegression, exibimos os coeficientes da reta (coeficiente angular e intercepto), e avaliamos o desempenho com três métricas: R², MAE e RMSE. Por fim, aplicamos validação cruzada com 5 subconjuntos e plotamos a reta de regressão obtida.
Atenção: Os dados utilizados neste código são simulados e gerados aleatoriamente dentro do próprio código — não representam imóveis reais.
Python 🐍 — regressao_linear.py 
# ── Bloco 1: Importações ─────────────────────────────────────────────
import numpy as np
# → numpy: cálculos vetoriais e geração de dados aleatórios
import matplotlib.pyplot as plt
# → matplotlib: criação do gráfico da reta de regressão
from sklearn.linear_model import LinearRegression
# → LinearRegression: o modelo de regressão linear (y = ax + b)
from sklearn.model_selection import train_test_split, cross_val_score
# → train_test_split: divide os dados em treino/teste
#   cross_val_score: avaliação cruzada (k-fold)
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
# → métricas para avaliar o desempenho do modelo: MAE, RMSE e R²

# ── Bloco 2: Criar dados simulados de imóveis ────────────────────────
np.random.seed(42)                                       # garante que os dados gerados são sempre os mesmos
X = 2.5 * np.random.randn(100, 1) + 25                  # tamanho do imóvel (m²), média ≈ 25 m²
y = 500 + (X * 20) + np.random.randn(100, 1) * 10       # preço do imóvel (R$ mil): a cada 1 m² a mais, +R$ 20 mil

# ── Bloco 3: Definir Features e Labels ───────────────────────────────
features = X   # feature: variável de entrada — tamanho do imóvel
labels   = y   # label:   variável de saída — preço do imóvel (o que queremos prever)

# ── Bloco 4: Dividir em Treino e Teste ───────────────────────────────
X_train, X_test, y_train, y_test = train_test_split(
    features, labels, test_size=0.2, random_state=42
)
# → 80% dos dados para treino · 20% reservados para teste
#   random_state=42 garante a mesma divisão toda vez que o código rodar

# ── Bloco 5: Criar e treinar o modelo ────────────────────────────────
model = LinearRegression()    # cria o modelo de regressão linear
model.fit(X_train, y_train)   # treina: ajusta os coeficientes a e b da equação y = ax + b

# ── Bloco 6: Fórmula da Regressão Linear ─────────────────────────────
# y = ax + b   (polinômio de 1º grau)
# y → variável de saída    (preço do imóvel)
# x → variável de entrada  (tamanho do imóvel)
# a → coeficiente angular  (quanto o preço varia por m²)
# b → intercepto           (valor base quando x = 0)

# ── Bloco 7: Coeficientes da regressão ───────────────────────────────
print(f"Coeficiente angular (b1): {model.coef_[0][0]:.2f}")
print(f"Intercepto (b0): {model.intercept_[0]:.2f}")

# ── Bloco 8: Predições nos dados de teste ────────────────────────────
y_pred = model.predict(X_test)
# → aplica o modelo treinado nos dados de teste (que ele nunca viu antes)

# ── Bloco 9: Métricas de avaliação ───────────────────────────────────
r2   = r2_score(y_test, y_pred)                     # R²: quão bem o modelo se ajusta (0 = ruim · 1 = perfeito)
mae  = mean_absolute_error(y_test, y_pred)          # MAE: média dos erros absolutos em R$ mil
rmse = np.sqrt(mean_squared_error(y_test, y_pred))  # RMSE: penaliza erros grandes (raiz do erro quadrático médio)

print(f"\nMétricas de avaliação:")
print(f"R² no teste: {r2:.2f}")
print(f"Erro Médio Absoluto (MAE): {mae:.2f}")
print(f"Raiz do Erro Quadrático Médio (RMSE): {rmse:.2f}")

# ── Bloco 10: Avaliação cruzada (5-fold) ─────────────────────────────
cv_scores = cross_val_score(model, features, labels, cv=5, scoring='r2')
# → divide o dataset em 5 subconjuntos
#   treina em 4, testa no 5º — repete 5 vezes — e tira a média dos R²
print(f"\nMédia dos scores de validação cruzada: {cv_scores.mean():.2f}")

# ── Bloco 11: Gráfico da reta de regressão ───────────────────────────
plt.figure(figsize=(8, 6))
plt.scatter(X_test, y_test, color='blue', label='Dados reais')               # pontos azuis: dados reais de teste
plt.plot(X_test, y_pred, color='red', linewidth=2, label='Regressão Linear') # reta vermelha: modelo obtido
plt.xlabel("Tamanho do imóvel")
plt.ylabel("Preço do imóvel")
plt.title("Regressão Linear: Preço x Tamanho do Imóvel")
plt.legend()
plt.show()

Interpretando os resultados

O coeficiente angular obtido foi 19,43 e o intercepto foi 514,29 — ou seja, a fórmula do modelo é aproximadamente y = 19,43x + 514,29. As métricas de avaliação foram: R² = 0,94, MAE = 7,39 e RMSE = 9,34. A média dos scores de validação cruzada foi de 0,95 — uma boa média.

No gráfico, os pontos azuis representam os dados reais gerados no início do código. A reta vermelha é o modelo obtido — a fórmula matemática y = ax + b —, que nos permite inferir o valor de um imóvel a partir do seu tamanho. Alguns pontos estão bem sobre a reta, outros mais próximos e outros mais distantes. Essa distância entre o ponto e a reta representa o erro do modelo. Quanto mais distante, maior o erro. Um ponto muito fora da curva é chamado de outlier, e pode impactar negativamente nas métricas.

Atenção à qualidade dos dados: ao preparar e coletar o dataset, é fundamental evitar incluir outliers que possam prejudicar o desempenho do modelo. O modelo tenta se ajustar para reduzir o erro, mas dados que não pertencem ao padrão do conjunto não fazem sentido e distorcem os resultados.
Desafios no treinamento de modelos

Dois problemas comuns no treinamento de Machine Learning são o underfitting e o overfitting.

O overfitting (superajuste) ocorre quando o modelo tenta se ajustar a todos os dados do dataset durante o treinamento. Apesar de parecer ótimo, ele só prevê bem para os dados com os quais foi treinado — qualquer dado fora do dataset não será bem previsto, resultando em mau desempenho na prática.

Já o underfitting (subajuste) ocorre quando o modelo não vai bem nem com o conjunto de dados de treinamento. Modelos muito simples não conseguem compreender as características presentes no dataset e não conseguem generalizar ou prever corretamente — resultando em subajuste.

O objetivo é encontrar o equilíbrio: um modelo que generaliza bem, aprendendo os padrões reais dos dados sem decorar exemplos específicos (overfitting) e sem ser simples demais para capturá-los (underfitting).
Item 05Para Saber Mais: Entendendo a Avaliação de Modelos
Principais métricas de avaliação

Ao avaliar um modelo de Machine Learning, utilizamos métricas para medir seu desempenho e entender sua capacidade de generalização. As principais métricas para modelos de regressão são:

  • R² (Coeficiente de Determinação): Mede o quão bem os dados se ajustam ao modelo. Um valor próximo de 1 indica um bom ajuste; valores baixos sugerem que o modelo não explica bem os dados.
  • MAE (Erro Médio Absoluto): Representa a média dos erros absolutos entre as previsões e os valores reais. Quanto menor o MAE, melhor o modelo.
  • RMSE (Raiz do Erro Quadrático Médio): Semelhante ao MAE, mas dá mais peso a erros maiores — tornando-o mais sensível a outliers.

Além das métricas, é fundamental garantir que o modelo generalize bem para novos dados, evitando dois problemas comuns:

Overfitting (Superajuste)

O modelo memoriza os dados de treino, mas vai mal nos dados de teste. Sinal: R² alto no treino e baixo no teste.

Underfitting (Subajuste)

O modelo é simples demais para capturar os padrões dos dados. Sinal: R² baixo tanto no treino quanto no teste.

Validação cruzada (Cross-Validation)

Uma técnica que podemos adotar para avaliar o desempenho do modelo sem depender de uma única divisão entre treino e teste é a validação cruzada. No código do Item 04, usamos cross_val_score(model, features, labels, cv=5, scoring='r2'), que divide os dados em 5 partes: treina o modelo em 4 e testa na parte restante. Esse processo é repetido até que todas as partes sejam usadas como teste — e a média dos resultados indica a capacidade do modelo de generalizar para novos dados.

Analogia: em vez de aplicar uma única prova para avaliar um aluno, o professor aplica cinco provas diferentes e calcula a média. O resultado final é mais justo e representativo do real conhecimento — da mesma forma, a validação cruzada fornece uma avaliação mais robusta do modelo.
Uma boa média de validação cruzada próxima ao R² do conjunto de teste indica que o modelo está generalizando bem — sem overfitting nem underfitting.
